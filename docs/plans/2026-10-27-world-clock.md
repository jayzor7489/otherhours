# World Clock Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A macOS WidgetKit widget (medium and large) that shows the user's own time plus any number of typed cities, each with a flag and a day/night coloured bar, configured from Apple's Edit Widget panel, built without Xcode.

**Architecture:** A SwiftPM package. `WorldClockCore` (pure logic, tested), `WorldClockViews` (SwiftUI rows, no WidgetKit), `WorldClockWidget` (executable target linked as an app extension: intent, provider, widget), `WorldClock` (host app), `WorldClockPreview` (renders PNGs of the views for visual checks, since Claude can't screenshot the desktop). `scripts/build.sh` assembles the `.app` with the `.appex`, writes the App Intents metadata by hand, signs ad-hoc, installs and registers.

**Tech Stack:** Swift 6 toolchain in Swift 5 language mode, SwiftUI, WidgetKit, AppIntents, Swift Testing, Python 3 for two generator scripts, Command Line Tools only.

**Spec:** `docs/specs/2026-10-27-world-clock-design.md` (read it first). Mockups: `docs/mockups/visual-style.html` (option B) and `docs/mockups/medium-four-rows.html` (option 2).

## Global Constraints

- No Xcode. Every Swift command exports `SDKROOT=/Library/Developer/CommandLineTools/SDKs/MacOSX26.5.sdk` (macOS 27 SDK needs Xcode for SwiftUI macros). Tests run through `scripts/test.sh`, which also passes the Swift Testing plugin path (copy Desk Pet's `scripts/test.sh` verbatim).
- `swift-tools-version:6.0`, `platforms: [.macOS(.v14)]`, `swiftLanguageModes: [.v5]` (as Desk Pet).
- Extension binary must import `_NSExtensionMain` (linker `-e _NSExtensionMain`), be signed ad-hoc with `com.apple.security.app-sandbox = true`, `CFBundlePackageType XPC!`, `NSExtensionPointIdentifier com.apple.widgetkit-extension`. Sign the `.appex` first, then the app.
- The only configuration parameter is a `String` named `cities` (dropdowns don't decode without Xcode; spec "How it gets built" step 6). Default value: `Denver, London, Sydney`.
- Sizes: `.systemMedium` and `.systemLarge` only.
- Install path is absolute: `~/Applications/World Clock.app` (`$HOME` differs in Claude's sessions).
- Bundle ids: `com.jasonaldemita.worldclock` (app), `com.jasonaldemita.worldclock.widget` (extension). Widget kind `WorldClock`, display name `World Clock`, description `Any number of cities, coloured by day and night.`
- Minus sign in offsets is U+2212 (`−`), not a hyphen. No em or en dashes in user-facing copy.
- City data: GeoNames `cities15000`, CC BY 4.0, attribution `City data from GeoNames (geonames.org), CC BY 4.0.` in the host app window and README.
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Never push; no remote.

## Review Focus

1. **Name collisions and suffixes.** "New York" and "Cebu" are stored by GeoNames as "New York City" and "Cebu City"; "Sydney" exists in Australia and Canada. Expect the obvious city. Tests in Task 2.
2. **Date line and half-hour zones.** Auckland and Honolulu are on different days; India is +2:30 from Manila, Kathmandu +2:15. Expect correct day word and `+5:30`-style offsets. Tests in Task 3.
3. **DST changeover inside one timeline.** Denver changes on 2026-11-01 at 02:00 local; entries on either side must show different offsets. Test in Task 3.
4. **Messy typing.** `" denver,,LONDON , "`, a trailing comma, the user's own city typed again, the same city twice. Expect clean rows, no blanks, no duplicate of the "you" row. Tests in Tasks 1 and 4.
5. **Monochrome/tinted widget style.** Hue is stripped; day/night must still read via brightness and SF Symbols. Preview render in Task 5, manual check in Task 7.
